# QuizUpdater

Нативное macOS-приложение для обновления Keynote-презентации квиза: превью всех
слайдов прямо в приложении, выбор нужного слайда кликом мыши, обновление таблицы
рейтинга и подстановка имён команд-призёров из таблицы результатов на Google Drive, а также заполнение
карточек предстоящих игр данными с сайта расписания — вместо ручных запусков
Python-скриптов из терминала с номерами слайдов вслепую.

---

## 1. Задача, которую это решает

Ведущий квизов после каждого раунда считает баллы команд в таблице на
Google Drive (Google Sheets или загруженный `.xlsx`) и должен отразить это в презентации Keynote, которая
показывается на экране во время игры: обновить общую таблицу рейтинга и,
в конце игры, на слайдах-«визитках» призовых мест подставить название
команды-победителя вместо текста-заглушки.

Раньше это делалось так: два Python-скрипта (`update_keynote_rating.py`,
`update_keynote_names.py`) запускались из терминала, а номер нужного слайда
нужно было знать/помнить заранее и передавать флагом (`--slide 81`,
`--start-slide 182 --places 1 2 3 8`) — легко ошибиться, неудобно во время
живого мероприятия, когда счёт времени идёт на секунды между раундами.

QuizUpdater убирает эти два неудобства:
- **не нужно помнить номера слайдов** — они выбираются кликом по превью;
- **не нужен терминал** — обычное macOS-приложение с окном и кнопками.

При этом вся логика разбора таблицы и работы с Keynote — та же самая, что была
в скриптах (перенесена почти без изменений), так что поведение предсказуемо
и совместимо с уже отработанным на реальных играх процессом. Изменился только
источник данных: таблица берётся прямо с Google Drive через API (раздел 5.6),
а не из локального файла в папке Drive for Desktop.

## 2. Архитектура: как это устроено

Приложение состоит из двух слоёв, которые вместе упакованы в один `.app`:

```
┌─────────────────────────────────────────────────────────────┐
│  QuizUpdater.app                                             │
│                                                                │
│  ┌───────────────────────┐        ┌──────────────────────┐   │
│  │   Swift / SwiftUI      │  JSON  │   Python-бэкенд       │   │
│  │   (интерфейс,          │◄──────►│   quiz_backend         │   │
│  │   Contents/MacOS)       │ stdout │   (Contents/Resources) │   │
│  └───────────┬─────────────┘        └───────────┬────────────┘   │
│              │ Process (subprocess)              │ osascript      │
└──────────────┼───────────────────────────────────┼────────────────┘
               │                                    ▼
               │                          ┌──────────────────┐
               │                          │   Keynote.app     │
               │                          │  (открытая        │
               │                          │   презентация)    │
               │                          └──────────────────┘
               │
               ├──► ~/Library/Caches/QuizUpdater/
               │    (кэш JPEG-превью слайдов)
               │
               └──► ~/Library/Application Support/QuizUpdater/
                    (ключ сервисного аккаунта Google, права 0600)

      Python-бэкенд ──HTTPS──► Google Drive API (только чтение)
```

**Почему два слоя, а не один язык.** Вся бизнес-логика (чтение Excel,
генерация и выполнение AppleScript) была уже написана, отлажена и проверена
на реальных играх на Python — переписывать её на Swift means риск незаметно
сломать рабочую логику ради красоты стека. Поэтому Python-логику просто
перенесли в отдельный модуль почти без изменений и переиспользовали, а Swift
отвечает только за интерфейс: превью слайдов, кнопки, кликабельный выбор.
Swift-приложение обращается к Python-бэкенду как к чёрному ящику — запускает
его как подпроцесс с аргументами командной строки и читает результат в виде
JSON из stdout.

**Почему Python встроен внутрь `.app`, а не Docker.** Изначально
рассматривался вариант "поднять бэкенд в Docker-контейнере", но это
принципиально не работает для этой задачи: управление Keynote идёт через
Apple Events/AppleScript, которые работают только между процессами прямо
на самом Mac — из Linux-контейнера Docker Desktop нет доступа ни к Keynote,
ни к `osascript`. Вместо этого Python и его зависимости
(`openpyxl` для разбора `.xlsx`, `rsa` + `pyasn1` для подписи JWT при обращении к Google —
все три чисто питоновские, без нативных библиотек) вендорятся (копируются) прямо внутрь
`Contents/Resources/backend` при сборке. Само приложение при запуске
использует системный `/usr/bin/python3` (тот, что ставится вместе
с Xcode Command Line Tools и есть на любом Mac, где вообще можно
разрабатывать/собирать софт) — пользователю не нужно ничего ставить:
ни conda, ни pip, ни Docker. Открыл `.app` — бэкенд "поднялся" сам как
дочерний процесс на каждый запрос. Системный Python — это 3.9.6 с LibreSSL 2.8.3,
поэтому весь бэкенд обязан оставаться совместимым с Python 3.9 (никаких `X | Y`
в рантайме, `match` и т. п.), а HTTP-запросы к Google идут через `urllib` из стандартной
библиотеки (TLS 1.2 этот LibreSSL поддерживает, CA берутся из `/private/etc/ssl/cert.pem`).

**Почему AppleScript, а не какой-то API Keynote.** У Keynote нет отдельного
API для управления открытым документом — единственный официальный способ
скриптово взаимодействовать с уже открытой презентацией на экране (не
с файлом на диске, а именно с «живым» документом, который видит зритель) —
это AppleScript-словарь приложения (Standard Additions + Keynote Suite).
И старые скрипты, и новый бэкенд используют один и тот же механизм: Python
собирает текст AppleScript-программы и выполняет её через системную утилиту
`osascript`.

## 3. Технологический стек

| Компонент | Технология | Почему |
|---|---|---|
| Интерфейс | Swift + SwiftUI, Swift Package Manager (без `.xcodeproj`) | нативный вид/ощущение Mac-приложения; SwiftPM собирает universal binary без танцев с Xcode-проектом (хватает Command Line Tools) |
| Автоматизация Keynote | AppleScript через `osascript` | единственный способ управлять уже открытым документом Keynote |
| Источник таблицы | Google Drive API v3 через `urllib` + сервисный аккаунт (JWT RS256 подписывает `rsa`), scope `drive.readonly` | нужен доступ только на чтение; сервисному аккаунту не нужен токен пользователя, который протухает (у OAuth-приложения в режиме Testing refresh-токен живёт 7 дней) |
| Разбор `.xlsx` | Python + `openpyxl` (из байтов, без файла на диске) | чистый Python, не требует компиляции под архитектуру — легко «вендорить» в бандл |
| Связь Swift ↔ Python | `Process` (Foundation) + JSON по stdout/stdin | простой, отлаживаемый контракт: каждую команду бэкенда можно вручную запустить и проверить из терминала |
| Превью слайдов | AppleScript-команда Keynote `export ... as slide images` → JPEG, кэш на диске | сам Keynote умеет рендерить слайды в картинки, велосипед не нужен |
| Упаковка | Makefile: `swift build --triple` под каждую архитектуру + `lipo` + `codesign --sign -` (ad-hoc) | universal binary без Apple Developer-аккаунта — для личного использования на двух своих Mac этого достаточно |

Целевая платформа — macOS 13 (Ventura) и новее, Intel и Apple Silicon
(один и тот же файл `.app` работает на обоих благодаря universal binary).

## 5. Как это работает «под капотом»

### 5.1 Контракт между Swift и Python

Swift запускает Python как обычный подпроцесс:

```
python3 -m quiz_backend <подкоманда> [--аргументы...]
```

Бэкенд **всегда** печатает в stdout ровно один JSON-объект и ничего больше
(предупреждения библиотек уходят в stderr, не мешая парсингу):

```jsonc
// успех
{"ok": true, /* поля, зависящие от подкоманды */}

// ошибка — понятный русский текст + машиночитаемый код
{"ok": false, "code": "AUTOMATION_DENIED", "error": "Нет разрешения на управление Keynote..."}
```

Swift сначала декодирует только `{ok, code, error}`, чтобы понять — это
успех или ошибка, и лишь потом (если `ok: true`) декодирует полный,
специфичный для команды набор полей. Так интерфейс всегда может показать
пользователю понятную русскую ошибку, даже если сама подкоманда упала
с исключением где-то в середине работы.

### 5.2 Подкоманды бэкенда

| Подкоманда | Что делает | Ключевые аргументы |
|---|---|---|
| `list-documents` | Список открытых в Keynote документов и число слайдов в каждом | — |
| `drive-status` | Подключён ли Google Drive на этом Mac и адрес робота (читает ключ с диска, **без сети**) | — |
| `connect-drive` | Проверяет ключ сервисного аккаунта запросом к Drive и только потом копирует его в `~/Library/Application Support/QuizUpdater/` (права `0600`); неудачная попытка не затирает прежний рабочий ключ | `--key` |
| `list-sheets` | Google Sheets и `.xlsx`, доступные роботу, свежие (по `modifiedTime`) первыми | — |
| `resolve-link` | Достаёт ID файла из ссылки Google Drive/Sheets и проверяет, что робот его видит и это таблица | `--link` |
| `read-sheet` | Скачивает таблицу заново и читает команды | `--file-id`, `--rounds` |
| `export-previews` | Экспортирует все слайды документа как JPEG (через `export ... as slide images` в Keynote) | `--doc`, `--out` |
| `update-rating` | Записывает данные таблицы с Drive в таблицу Keynote на выбранном слайде; число раундов берёт из этой таблицы (колонки минус 3), а число строк подгоняет под число команд (добавляет недостающие, удаляет лишние); `--dry-run` показывает и то и другое, ничего не меняя | `--doc`, `--slide`, `--file-id`, `--max-rows`, `--dry-run` |
| `replace-names` | Заменяет текст-плейсхолдер «ЗАМЕНИТЬ» именами команд на слайдах мест 1–3 и **создаёт слайды дополнительных мест 4+ из слайда-шаблона** (раздел 5.7) | `--doc`, `--file-id`, `--pairs "место:слайд,..."`, `--extra-places "13,5,4"`, `--template-slide`, `--dry-run` |
| `fetch-schedule` | Загружает список предстоящих игр с сайта расписания | — |
| `fill-schedule-slots` | Заполняет карточки игр текстовыми полями на выбранном слайде | `--doc`, `--slide`, `--games '<json>'`, `--dry-run` |

Каждую команду можно запустить и проверить прямо из терминала — это
основной способ отладки, если что-то в приложении ведёт себя не так:

```bash
cd quiz
export PYTHONPATH=backend:backend/vendor
/usr/bin/python3 -m quiz_backend list-documents
/usr/bin/python3 -m quiz_backend drive-status
/usr/bin/python3 -m quiz_backend list-sheets          # ID нужной таблицы берётся отсюда
/usr/bin/python3 -m quiz_backend update-rating --slide 81 --file-id <ID> --dry-run
```

Коды ошибок, которые бэкенд может вернуть. Интерфейс показывает соответствующий
русский текст в статус-баре внизу окна (и в окне выбора таблицы):

| Код | Когда | Что ещё показывает интерфейс |
|---|---|---|
| `DRIVE_NOT_CONNECTED` | на этом Mac нет ключа | кнопка «Подключить Google Drive…» |
| `DRIVE_KEY_INVALID` | файл — не ключ сервисного аккаунта / повреждён | кнопка «Подключить Google Drive…» |
| `DRIVE_AUTH_FAILED` | Google не принял ключ (удалён/отозван), отклонил запрос (401), в проекте не включён Drive API | кнопка «Подключить Google Drive…» |
| `FILE_NOT_SHARED` | файл не расшарен роботу (Google отвечает 404 или 403) | сообщение с адресом робота и кнопка «Скопировать» (адрес приходит в поле `clientEmail`) |
| `NETWORK_ERROR` | нет сети или Google недоступен (после повторов) | — |
| `INVALID_LINK` | вставленный текст не похож на ссылку на файл Google Drive | — |
| `DRIVE_ERROR` | прочие ошибки Drive (в т.ч. исчерпаны повторы при 5xx/лимитах) | — |
| `EXCEL_BAD_FORMAT` | файл не таблица, не открывается как `.xlsx`, нет листа `Лист1` (в тексте — список листов) | — |
| `TEMPLATE_INVALID` | на слайде нет таблицы рейтинга / в ней меньше 3 колонок; не найдены 4 пары полей расписания; на слайде-шаблоне нет текстов «НОМЕР» и «ЗАМЕНИТЬ» | — |
| `KEYNOTE_NOT_RUNNING`, `DOC_NOT_FOUND`, `APPLESCRIPT_ERROR`, `INVALID_ARGUMENT` | как раньше | — |
| `AUTOMATION_DENIED` | нет разрешения на управление Keynote | кнопка «Открыть настройки» |

### 5.3 Превью слайдов и кэш

По кнопке «Обновить превью» приложение вызывает `export-previews`, который
одной AppleScript-командой просит Keynote отрендерить все слайды документа
в JPEG во временную папку (Keynote сам её создаёт). Для презентации на
~200+ слайдов это занимает 30–50 секунд — прогресс-бар в приложении в это
время просто считает, сколько файлов уже появилось в папке.

Результат кэшируется в `~/Library/Caches/QuizUpdater/<хэш_имени_документа>/`.
При повторном открытии того же документа (если число слайдов не
изменилось) превью подгружаются из кэша мгновенно, без повторного
экспорта. Кнопка «Обновить превью» сбрасывает кэш принудительно.

### 5.4 Разрешение на управление Keynote (TCC)

При первом реальном обращении к Keynote macOS покажет системный диалог:
«QuizUpdater хочет получить доступ для управления Keynote» — это стандартная
защита macOS (Automation/TCC), а не ошибка приложения. Нужно один раз
нажать «Разрешить». Управляется в Настройки → Конфиденциальность
и безопасность → Автоматизация.

Поскольку приложение подписано ad-hoc-подписью (без Apple Developer
аккаунта — не нужен для личного использования), эта подпись меняется
при каждой пересборке `make app`, и macOS будет заново спрашивать
разрешение после каждой пересборки. Для повседневного использования
(без пересборок) разрешение запоминается один раз.

### 5.5 Карточки расписания игр — как это устроено

Режим «Расписание игр» заполняет на выбранном слайде до 4 «карточек» предстоящих игр
данными с сайта `sofia.quizplease.ru` (реальный JSON API `api.quizplease.com`, без браузера/JS).

**Важное техническое ограничение Keynote**, определившее весь дизайн: AppleScript в этой
версии Keynote не может ни создать новую фигуру/группу с нужным цветом (`shape`/`group` не
имеют свойств заливки/обводки/скругления), ни продублировать существующую (`duplicate`
работает только для целых слайдов, не для фигур/таблиц — «Shapes can not be copied»). Поэтому
приложение ничего не рисует и не копирует — оно только находит и заполняет текстом уже
существующие на слайде текстовые поля, которые пользователь готовит сам:

1. На выбранном слайде вручную (обычный Text tool в Keynote, без группировки и без Cmd+G)
   создаются **4 пары** текстовых полей: левое поле каждой пары — под тему+номер игры,
   правое — под дату, примерно на одной высоте друг с другом. Остальной контент слайда
   (заголовок, фон, футер) не трогается.
2. Приложение находит эти пары **по расположению**, а не по содержимому текста: все
   текстовые поля слайда группируются по Y-координате (в пределах допуска — Keynote слегка
   двигает рамку поля при автоподгонке под контент), декоративные надписи (заголовок и т.п.)
   остаются «строкой» с одним элементом и отбрасываются, а пары полей — «строкой» из двух
   элементов, где левый по X — тема, правый — дата.
3. Найденные пары сортируются по (Y, X) → это и есть слоты 1–4 (сверху вниз, слева направо).
   Игры (уже отсортированы по дате) занимают слоты по порядку; если игр меньше 4 — лишние
   слоты просто очищаются (пустой текст), если больше — показываются первые 4 по дате.
4. Размер шрифта левого поля подбирается автоматически (`schedule.compute_card_font_size`):
   короткий текст (`#NN`) — как в шаблоне, длинная тема — пропорционально мельче (не меньше
   16pt), чтобы не вылезать за рамку карточки.

Поскольку идентификация — по позиции, а не по уникальному тексту-маркеру, повторный запуск
полностью безопасен и идемпотентен: старый текст просто заменяется новым, ничего не
накапливается и не нужно ничего удалять вручную перед следующим прогоном.

### 5.6 Google Drive: доступ и данные

- **Авторизация — сервисный аккаунт («робот»).** Ключ лежит в
  `~/Library/Application Support/QuizUpdater/service-account.json` (права `0600`, каталог `0700`).
  Бэкенд подписывает JWT (RS256), меняет его на access token (живёт только в памяти на время одной
  команды) со scope `drive.readonly` — запись в Drive технически невозможна. Ключ в репозиторий не
  попадает; тесты генерируют свой RSA-ключ на лету.
- **Робот видит только то, что ему расшарено.** По замыслу расшаривается папка `КВИЗ` с подпапками,
  таблицы игр хранятся в ней (настройка — раздел 8).
- **Список таблиц** — один запрос `files.list` по mimeType (Google Sheets и `.xlsx`), без корзины, свежие
  по `modifiedTime` сверху, все страницы. Поиск по названию в окне — на стороне приложения. Обхода
  дерева папок нет: проверено на реальном Drive, что если расшарена только папка, то робот видит её
  и файлы внутри неё. Вложенные подпапки на реальных данных не проверялись (доступ в Drive
  наследуется вглубь, но в `КВИЗ` подпапок на момент проверки не было); если таблица в подпапке не
  появилась в списке — её всё равно можно выбрать по ссылке.
- **Скачивание.** Google Sheets выгружаются через `files.export` в xlsx, загруженный `.xlsx` — через
  `files.get?alt=media`. Дальше тот же `openpyxl`, только из байтов. **Содержимое не кэшируется:**
  таблица скачивается заново при каждом действии (загрузка команд, «Проверить», «Обновить таблицу»,
  «Заменить имена»), поэтому правка в Google Sheets видна при следующем действии без перезапуска.
- **Повторы.** При 429, 500/502/503/504 и «rate limit» (403 `rateLimitExceeded`/`userRateLimitExceeded`)
  и при сетевых сбоях запрос повторяется ещё дважды с паузой 1 и 2 секунды (на живой игре ведущий не
  должен ждать долго). 401 и обычные 403/404 не повторяются — это не транзиентные ошибки.
- **Выбор таблицы** запоминается в UserDefaults (ID файла и название для отображения) и действует,
  пока ведущий не выберет другую. Ссылку можно вставить вместо выбора из списка: из `docs.google.com`/
  `drive.google.com` достаётся ID (`/d/<ID>/…`, `open?id=<ID>`); ссылки «Опубликовать в Интернете»
  (`/d/e/…`) и ссылки на папки не подходят.
- **Число раундов задаёт Keynote.** N = число колонок «Таблицы 1» (`table 1`) на выбранном слайде минус 3
  (место, команда, итого). Из таблицы на Drive берутся ровно N колонок начиная с D.
- **Число строк подгоняется под число команд.** Строк в таблице Keynote становится столько, сколько команд на
  Drive, но не больше лимита «Команд не больше: N» (`--max-rows`): недостающие добавляются, лишние удаляются
  с конца, чтобы в них не оставались данные прошлой игры. Делается свойством `row count` таблицы; оформление
  (полосатая заливка) продолжается само. Если на Drive нет ни одной команды, это ошибка, а не пустая таблица.
  Keynote при смене числа строк **сохраняет общую высоту таблицы** и пересчитывает высоту строк, поэтому при
  добавлении строк они становятся тоньше. «Проверить» предупреждает, если новые строки окажутся ниже шрифта
  (высота строки < 1,3 × размер шрифта) и текст может обрезаться.

### 5.7 Дополнительные места: слайды из шаблона

Места 1, 2, 3 — нестандартные слайды, подготовленные заранее: приложение только заменяет на них
«ЗАМЕНИТЬ» названием команды, а слайд для места берётся **по номеру места** от слайда 1-го места
(1-е = слайд, на который кликнули, 2-е = перед ним, 3-е = ещё раньше), а не по порядку выбора.

Остальные места, которые выберет ведущий, создаются автоматически из **слайда-шаблона** «НОМЕР МЕСТО»:
на нём два текстовых поля, «НОМЕР» и «ЗАМЕНИТЬ» (слово «МЕСТО» остаётся как есть).

- **Порядок — обратный отсчёт**, как у мест 1–3: от большего места к меньшему, перед слайдом 3-го места
  (например, 13-е → 7-е → 4-е → 3-е → 2-е → 1-е).
- **Как создаётся:** шаблон дублируется (`duplicate slide … to before slide …`) на одну копию меньше, чем
  дополнительных мест; копии идут над шаблоном, а сам шаблон достаётся **самому младшему** из дополнительных
  мест. Все копии делаются с нетронутого шаблона, затем заполняются. Анимации и оформление слайда копируются.
- **«НОМЕР» заменяется порядковым числительным заглавными**, среднего рода (`ordinals.py`, 1–100):
  9 → «ДЕВЯТОЕ», 14 → «ЧЕТЫРНАДЦАТОЕ», 23 → «ДВАДЦАТЬ ТРЕТЬЕ», «ЧЕТВЁРТОЕ» с «Ё».
- **Длинные числительные уменьшают шрифт поля:** при шрифте шаблона «ЧЕТЫРНАДЦАТОЕ» (13 знаков) помещается,
  «ДВАДЦАТЬ ВОСЬМОЕ» упирается в края слайда, а «ВОСЕМЬДЕСЯТ ВОСЬМОЕ» переносится и налезает на «МЕСТО»
  (проверено на реальных слайдах), поэтому шрифт уменьшается пропорционально длине (`ordinal_font_scale`).
- **Слайд-шаблон** по умолчанию — слайд перед слайдом 3-го места; его можно поправить в приложении. «Проверить»
  убеждается, что на нём есть и «НОМЕР», и «ЗАМЕНИТЬ» (иначе `TEMPLATE_INVALID`).
- **Если дополнительных мест нет**, неиспользованный шаблон скрывается из показа (`skipped`), чтобы на экране
  не появилось «НОМЕР МЕСТО / ЗАМЕНИТЬ»; уже использованный шаблон не трогается.
- **Повторный запуск безопасен:** в использованном шаблоне нет «НОМЕР», поэтому вместо лишних копий придёт
  ошибка. После создания слайдов номера в документе сдвигаются: приложение обновляет документ и превью.

## 6. Сборка

Достаточно Xcode Command Line Tools (`xcode-select --install`), полный Xcode не нужен: с ними
идут и Swift, и системный `/usr/bin/python3` с `pip`. Universal-бинарь собирается по одной
архитектуре (`swift build --triple …`) и склеивается `lipo` — одна команда `--arch arm64 --arch x86_64`
требовала бы `xcbuild` из полного Xcode. `make vendor` ставит им `openpyxl`, `rsa` и `pyasn1` в `backend/vendor/`
— тем же интерпретатором, на котором бэкенд будет работать в бандле, поэтому pip выбирает версии,
совместимые с Python 3.9. Ставятся только pure-Python wheels, и сборка падает, если в `backend/vendor/`
попала нативная библиотека (иначе бандл перестал бы быть universal). Пользователю при использовании
собранного `.app` ничего ставить не нужно.

```bash
make app     # соберёт dist/QuizUpdater.app (universal binary, ad-hoc подпись)
make run     # то же самое + сразу открыть приложение
```

Проверить, что бинарь действительно universal:
```bash
lipo -archs dist/QuizUpdater.app/Contents/MacOS/QuizUpdater   # ожидается: x86_64 arm64
```

Тесты бэкенда системным Python 3.9 (та же версия, что использует бандл — на случай, если в код
случайно попадёт синтаксис новее):
```bash
make test-backend
```
Сеть и ключ Google для них не нужны: настоящий `urllib` ходит на локальный фейк Google Drive,
подпись JWT проверяет `openssl`, тестовый RSA-ключ генерируется на лету. После тестов выполняются два
безопасных прогона подкоманд — `drive-status` (без сети) и `list-documents` (только читает Keynote).

### Разработка (без пересборки `.app` на каждое изменение)

```bash
QUIZ_BACKEND_DIR="$(pwd)/backend" swift run --package-path app
```

В этом режиме ответственным за Apple Events (и разрешение TCC) будет
терминал, а не `QuizUpdater.app` — финальную проверку разрешений делайте
через `open dist/QuizUpdater.app`.

## 7. Перенос на другой Mac (в т.ч. Intel)

**Вариант 1 — собрать на месте (надёжнее всего):**
```bash
# скопировать репозиторий на целевой Mac любым способом, затем:
make app && make run
```

**Вариант 2 — перенести уже собранный `.app`:**
- через scp/USB/локальную сеть — работает сразу;
- через AirDrop/скачивание из интернета — macOS помечает файл атрибутом
  quarantine, Gatekeeper заблокирует запуск ad-hoc-подписанного
  приложения. Снять карантин на целевом Mac:
  ```bash
  xattr -dr com.apple.quarantine /Applications/QuizUpdater.app
  ```

На целевом Mac должен быть Python 3 (для запуска уже собранного
бэкенда) — проще всего через Command Line Tools:
```bash
xcode-select -p || xcode-select --install
```
Устанавливать Python-зависимости на целевой машине не нужно — они уже внутри `.app`.
Ключ Google вместе с `.app` не переезжает: на каждом Mac один раз нужно нажать
«Подключить Google Drive…» (раздел 8).

## 8. Подключение Google Drive (один раз)

Нужно один раз настроить сервисный аккаунт и один раз на каждом Mac подключить его ключ.

**В Google (один раз):**

1. Google Cloud Console → нужный проект (тот же, что у quiz-ai, или новый) → APIs & Services →
   включить **Google Drive API**.
2. IAM & Admin → Service Accounts → **Create service account** (например, `quiz-updater`). Роли в
   проекте не нужны.
3. Открыть созданный аккаунт → Keys → Add key → Create new key → **JSON**. Скачается файл-ключ;
   **в репозиторий его не класть**. Если создание ключа запрещено политикой, значит проект принадлежит
   организации; у личного gmail-проекта без организации такого ограничения нет.
4. Google Drive → папка `КВИЗ` → «Поделиться» → адрес робота
   (`quiz-updater@<project>.iam.gserviceaccount.com`) → роль **Читатель**, уведомление отключить.
5. Таблицы результатов игр (например, `Классика #59 результаты`) хранить в `КВИЗ`.

**На каждом Mac:** QuizUpdater → кнопка с облаком рядом с «Выбрать…» или «Подключить Google Drive…» в
сообщении об ошибке → выбрать JSON-ключ. Приложение копирует его в
`~/Library/Application Support/QuizUpdater/`, сразу проверяет доступ и пишет «Подключено, таблиц
доступно: N». Там же показан адрес робота с кнопкой «Скопировать» — если таблицы не видны или файл не
расшарен, нужно дать доступ «Читатель» именно этому адресу. Чтобы отозвать доступ, удалите ключ в
Cloud Console (Keys → Delete) и файл `service-account.json` из Application Support.

## 9. Использование

1. Откройте нужную презентацию `.key` в Keynote (как обычно).
2. Откройте `QuizUpdater.app` — вверху выберите документ Keynote и таблицу результатов
   («Выбрать…»: список таблиц, доступных роботу, свежие сверху, поиск по названию, либо вставьте
   ссылку на таблицу; выбор запоминается; кнопка с двумя стрелками перечитывает таблицу, когда результаты
   изменились), нажмите «Обновить превью».
3. **Режим «Таблица рейтинга»**: кликните по слайду с таблицей рейтинга
   на превью слева, задайте число команд (стрелочки «Команд: N»),
   нажмите «Проверить» — приложение покажет, что будет записано (сколько раундов — их число задаёт сама
   таблица в Keynote — и сколько строк добавится или удалится), ничего не меняя в Keynote, — затем
   «Обновить таблицу». Поле «Команд не больше» ограничивает число команд, а значит и строк.
   Данные таблицы скачиваются заново при каждом нажатии.
4. **Режим «Имена призёров»** (подробности — раздел 5.7): отметьте нужные места галочками и кликните по
   слайду **1-го места** на превью. Места 1–3 возьмут готовые слайды по номеру места (можно поправить
   стрелочками), а все остальные отмеченные места (4+) приложение создаст из слайда-шаблона «НОМЕР МЕСТО»:
   по умолчанию это слайд перед слайдом 3-го места (поправляется стрелочками «Слайд-шаблон»). «Проверить»
   покажет план («дополнительные места: ТРИНАДЦАТОЕ, СЕДЬМОЕ, ЧЕТВЁРТОЕ; новых слайдов: 2»), подсветит на
   превью зелёным/красным, найдены ли плейсхолдеры, и ничего не изменит; затем «Заменить имена». Слайды
   создаются в документе по-настоящему (отменить — ⌘Z в Keynote), поэтому сначала «Проверить».
5. **Режим «Расписание игр»**: нажмите «Загрузить расписание» — появится
   чек-лист предстоящих игр (можно снять галочку с ненужной), кликните
   по слайду с 4 подготовленными парами текстовых полей (см. раздел 5.5 —
   слайд готовится один раз вручную), «Проверить» покажет предпросмотр
   заполнения слотов, затем «Заполнить карточки».

Рекомендуется на новой/незнакомой презентации сначала пройтись
«Проверить» (dry-run) — это ничего не меняет в Keynote, только
показывает, что будет сделано.

## 10. Формат таблицы результатов

Это контракт: приложение читает лист `Лист1` (Google Sheets или `.xlsx` на Drive), данные со 2-й строки
(первая строка — заголовки), чтение останавливается на первой пустой строке. Лист не угадывается: если
`Лист1` нет, приложение покажет ошибку со списком листов (соседний `Лист1 (копия)` не используется).

| Колонка | Содержимое |
| ------- | ---------- |
| A | Место |
| B | Команда |
| C | Итого |
| D и далее | Раунды. Берётся ровно столько колонок, сколько раундов в таблице Keynote: 7 колонок раундов в Keynote → 7 раундов, 8 → 8. Пустая ячейка на Drive становится пустой ячейкой в Keynote |

## 11. Структура таблицы рейтинга в Keynote

На целевом слайде — две таблицы: «Таблица 1» (данные, без заголовка,
любое число строк × (3 + число раундов) колонок — именно её обновляет приложение; число раундов
выводится из числа её колонок, а число строк подгоняется под число команд) и «Таблица 2» (заголовки,
приложением не изменяется).

## 12. Известные ограничения

- Экспорт превью ~180–230 слайдов занимает 30–50 секунд (один
  AppleScript-вызов без промежуточных колбэков — прогресс-бар считает
  уже созданные файлы, честного процента от Keynote получить нельзя).
- Кэш превью на диске инвалидируется только по числу слайдов документа;
  если содержимое слайдов поменялось без изменения их количества —
  нажмите «Обновить превью» вручную.
- Удаление строк в Keynote необратимо средствами приложения (отменить можно только ⌘Z в Keynote), поэтому
  сначала нажимайте «Проверить». При добавлении многих строк Keynote делает их тоньше (общая высота таблицы
  не меняется) — тогда крупный шрифт может обрезаться, об этом предупреждает «Проверить».
- Нужен интернет: без сети, без ключа или при нерасшаренном файле приложение показывает понятное
  сообщение, но офлайн-режима и кэша содержимого таблицы нет (каждое действие скачивает таблицу заново
  — это добавляет секунду-две к «Проверить» и «Обновить»).
- Робот видит только расшаренное ему; ключ нужно подключить на каждом Mac отдельно.
- Список команд в панелях «Таблица рейтинга»/«Имена призёров» загружается при запуске и при выборе
  таблицы и **сам не обновляется**: если результаты изменились, нажмите кнопку «Перечитать таблицу»
  (две круглые стрелки рядом с названием таблицы). В Keynote при каждом действии («Проверить»,
  «Обновить таблицу», «Заменить имена») записываются свежие данные с Drive и без этой кнопки (см. раздел 5.6).
- В списке выбора — только Google Sheets и `.xlsx`; лист всегда `Лист1`, другие шаблоны таблиц
  не поддерживаются.
- Ad-hoc подпись означает, что TCC-разрешение на управление Keynote
  запрашивается заново после каждой пересборки `make app` (см. раздел 5.4).
- **Расписание игр**: жёсткий лимит 4 карточки на слайд (лишние игры не показываются,
  учитываются первые 4 по возрастанию даты). Автоподбор размера шрифта учитывает только
  длину текста темы, но не реальную ширину текстового поля в Keynote — если поле узкое
  (сделано под короткое «#NN»), длинная тема всё равно может выглядеть мелко/переноситься
  на несколько строк; для лучшего результата расширьте это текстовое поле в Keynote вручную.
